# LLM Document Extractor

Тестовое задание LLM Engineer (задание А): извлечение данных из текста документа в JSON.
Планируемый интерфейс — простой CLI для текстовых файлов, без веб-интерфейса.

## Установка (Windows PowerShell, Python 3.11+)

Откройте терминал в папке проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

В `.env` укажите свой `OPENAI_API_KEY`. Модель по умолчанию — `gpt-5-nano`.
На первом этапе ключ не используется, платных запросов нет.
Если PowerShell запрещает активацию, используйте команды без неё:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

С активированным окружением:

```powershell
python main.py
python -m unittest discover -s tests -v
```

Сейчас `main.py` выводит статус подготовки. Это ещё не запуск извлечения.

## Структура

- `main.py` — точка входа.
- `extractor.py` — будущий вызов OpenAI API.
- `schemas.py` — Pydantic-модели `Document` и `LineItem`.
- `validators.py` — будущие проверки по тексту документа.
- `eval.py` — будущая оценка качества.
- `data/documents/` и `data/expected/` — документы и эталонные JSON.
- `tests/test_schemas.py` — проверки схем без API.
- `REFLECTION.md` — место для итоговой рефлексии и архитектурного ответа.

## Правила схемы и принятые решения

Все ключи результата обязательны. Отсутствующие скалярные данные передаются как
`null`, неизвестный тип — `unknown`. Если позиций или предупреждений нет,
передаются пустые списки. `field_confidence` — словарь имён полей и чисел от 0 до 1;
в PDF приведён пример с `supplier_bin`, но закрытый перечень ключей не задан.

БИН — строка из ровно 12 ASCII-цифр; дата — существующая календарная дата
строго в формате `YYYY-MM-DD`. Валюта и тип документа ограничены значениями
из задания. Числа не принимаются в виде строк или булевых значений; NaN и
бесконечность запрещены. Лишние ключи запрещены, в том числе внутри позиций.
Знак сумм, количества и цены не ограничен: такого ограничения в PDF нет.

Схема проверяет структуру и значения, но не подтверждает их наличие в тексте.
Запрет выдумывать данные, обработка противоречий и невалидного ответа LLM будут
реализованы в следующих этапах. Правило выбора при противоречиях будет описано
здесь вместе с реализацией.

## Текущий статус

Выполнен только этап 1: структура, окружение, схемы и их автотесты.
Извлечение, проверки по тексту, тестовые документы, эталоны и eval ещё не реализованы.
Далее нужны минимум 10 документов (3 из PDF и минимум 7 своих, включая 3 сложных),
оценка точности по полям, отдельный подсчёт галлюцинаций и пропусков.
Перед сдачей нужно проверить полный запуск в чистом окружении и заполнить REFLECTION.

Проверка этапа 1: четыре теста схем прошли на Python 3.11.5 / Pydantic 2.12.5
в установленном системном Python. Окружение `.venv` создано, но установка зависимостей
в него не завершилась: PyPI недоступен (ошибка DNS). После восстановления доступа
выполните команду установки выше и повторите тесты в `.venv`.
